# 3.2 — Infraestructura empresarial segura: aplicar principios de seguridad

## Objetivo del examen

Ante un escenario, debes poder seleccionar, ubicar y configurar controles que protejan la infraestructura empresarial sin perder de vista disponibilidad, rendimiento, operación y coste.

La **infraestructura de seguridad** reúne hardware, software, redes, datos, identidades, procesos y políticas que trabajan conjuntamente para proteger los activos. Un control aislado no basta: una buena arquitectura aplica defensa en profundidad, privilegio mínimo, segmentación, configuración segura, supervisión y recuperación.

> Principio guía: protege cada flujo de datos y cada frontera de confianza, pero evita añadir controles sin entender su impacto operacional y sus modos de fallo.

## Método para resolver escenarios

1. **Identifica el activo y su criticidad:** datos, aplicación, usuarios, proceso industrial o servicio público.
2. **Traza los flujos:** origen, destino, protocolo, puertos, identidad y red atravesada.
3. **Define zonas de confianza:** Internet, invitados, usuarios, servidores, administración, nube, OT/IoT, etc.
4. **Aplica controles por capas:** preventivos, detectivos, correctivos y de recuperación.
5. **Decide la ubicación:** perímetro, entre zonas, en el host, en línea o pasivo.
6. **Valida operación:** latencia, alta disponibilidad, logs, falso positivo, parcheado y comportamiento ante un fallo.

## 1. Puertos, protocolos y mínimo privilegio de red

Los puertos permiten que un host distinga servicios de red. Conocerlos no significa abrirlos: el principio correcto es **permitir solo los flujos necesarios**, desde los orígenes necesarios y hacia los destinos necesarios.

| Servicio habitual | Puerto(s) típico(s) | Uso y consideración de seguridad |
|---|---:|---|
| DNS | 53 TCP/UDP | Resuelve nombres; limita quién puede hacer transferencias de zona y usa resolutores autorizados |
| HTTP / HTTPS | 80 / 443 TCP | HTTP no cifra; HTTPS protege el canal con TLS, pero la aplicación sigue necesitando controles |
| SSH | 22 TCP | Administración remota segura; restringir orígenes, usar MFA/llaves y registrar sesiones |
| RDP | 3389 TCP/UDP | Administración gráfica; no exponerlo directamente a Internet; usar VPN/ZTNA o bastion host |
| SMTP | 25, 465, 587 TCP | Transporte y envío de correo; filtrar, autenticar y proteger contra abuso |
| IMAP / POP3 seguros | 993 / 995 TCP | Acceso a correo cifrado |
| SMB | 445 TCP | Compartición de archivos Windows; limitarlo a segmentos internos necesarios |
| LDAP seguro | 636 TCP | Directorio sobre TLS; restringir cuentas y consultas |

Los puertos pueden variar por aplicación o diseño. En un caso real se validan con inventario y documentación; no se debe abrir un puerto solo porque sea el puerto «normal» de un servicio.

### Reglas y listas de control de acceso (ACL)

Una ACL o política de firewall debe expresar quién puede comunicarse con quién y para qué. Una regla sólida especifica, como mínimo, origen, destino, servicio/protocolo, dirección, acción, duración y propietario.

Buenas prácticas:

- Denegar por defecto y permitir explícitamente lo imprescindible.
- Ser específico: una subred o identidad concreta es mejor que `any` cuando sea posible.
- Separar reglas temporales y eliminar las que ya no tengan justificación.
- Revisar orden de reglas, objetos, tráfico bloqueado y cambios aprobados.
- Registrar denegaciones relevantes y probar el flujo antes y después de un cambio.

## 2. Firewalls y segmentación

Un **firewall** filtra tráfico entrante y saliente según una política. Puede ser una appliance, un servicio cloud o software en un endpoint. Su finalidad es controlar comunicaciones entre redes o zonas de distinta confianza, no sustituir parcheado, identidad segura o protección de aplicaciones.

### Tipos y niveles de inspección

| Control | Qué analiza o hace | Cuándo resulta útil | Limitación principal |
|---|---|---|---|
| Filtrado de paquetes / L3-L4 | IP, protocolo y puertos; a menudo también estado básico | Segmentación rápida y políticas simples | No entiende por sí solo la intención ni el contenido de la aplicación |
| Firewall con estado | Mantiene una tabla de conexiones y permite respuestas asociadas | Perímetro y segmentación general | No detecta todos los ataques de capa de aplicación |
| Proxy / firewall de aplicación | Termina o intermedia conexiones y aplica reglas específicas de protocolo | Control detallado de HTTP, correo u otros protocolos | Mayor complejidad, latencia y necesidad de configuración correcta |
| **NGFW** | Firewall con estado más identificación de aplicaciones, inspección avanzada e integración frecuente con IPS | Políticas granulares y protección de perímetro/segmentos | Puede ser complejo, costoso y requiere ajuste continuo |
| **WAF** | Protege tráfico HTTP/HTTPS y lógica de aplicaciones web | Aplicaciones web frente a ataques como inyección o XSS | No reemplaza una aplicación segura ni un firewall de red |
| **UTM** | Consolida varias funciones: firewall, IPS, VPN, filtrado, etc. | Entornos que necesitan administración integrada | Puede concentrar capacidad y fallo; revisar rendimiento y alta disponibilidad |

«Capa 4» y «capa 7» describen de forma abreviada cuánto contexto puede usar el control. La inspección profunda puede aportar protección adicional, pero también aumenta latencia, consumo y riesgo de bloquear tráfico legítimo. Dimensiona el equipo con las funciones de inspección realmente activas, no solo con su rendimiento nominal.

### Firewall de host y firewall de red

- El **firewall de red** aplica reglas a un segmento o a un flujo entre zonas; centraliza el control.
- El **firewall de host** protege cada servidor o endpoint, incluso frente a movimiento lateral dentro de la misma red.

Se complementan. Un servidor de base de datos, por ejemplo, puede estar en una VLAN de datos, tener ACL entre VLAN y además aceptar en su firewall local únicamente conexiones del servidor de aplicación por el puerto de base de datos requerido.

### Zonas y screened subnet

Una **zona de seguridad** agrupa activos con un nivel de confianza y requisitos similares. Una **screened subnet** —a menudo llamada DMZ— aloja servicios expuestos como web, relay de correo o DNS autoritativo, separados de Internet y de la red interna.

```text
Internet ── Firewall perimetral ── Screened subnet / DMZ ── Firewall interno ── Red interna
                                     └─ web, relay, DNS                       └─ usuarios, datos
```

Que un servidor web esté en la DMZ no autoriza libre acceso a la base de datos interna. Se permiten solo los flujos estrictamente necesarios desde la DMZ hacia el interior. La «DMZ» no es un producto ni es exactamente lo mismo que un host con dos interfaces: es una zona diseñada y filtrada.

### WAF: en línea o fuera de banda

Un WAF **en línea** puede bloquear solicitudes en tiempo real; por ello requiere pruebas, ajuste de reglas, capacidad y alta disponibilidad. Un WAF o sensor **fuera de banda** recibe una copia del tráfico y sirve para visibilidad y alertas, pero por sí mismo no bloquea el paquete que ya circula.

## 3. IDS e IPS

Ambos buscan actividad sospechosa; su diferencia crítica es la respuesta.

| Sistema | Función | Ubicación habitual |
|---|---|---|
| **IDS** | Detecta, registra y alerta; no bloquea directamente | Pasivo, mediante TAP o puerto SPAN/mirror |
| **IPS** | Detecta y aplica una acción, como bloquear o reiniciar una conexión | En línea, dentro del flujo que se quiere proteger |

Un IPS puede reducir el tiempo de respuesta, pero un falso positivo puede interrumpir un servicio legítimo. Un IDS aporta excelente visibilidad con menor riesgo de interrupción, aunque depende de que alguien procese y responda a las alertas.

### Alcance del sensor

- **NIDS/NIPS:** observa o controla tráfico de red en un punto seleccionado. Es útil para ataques, escaneos y movimientos entre segmentos visibles para el sensor.
- **HIDS/HIPS:** agente en el host que observa procesos, archivos, registros, configuración y tráfico local. Ve actividad que puede estar cifrada en la red, pero exige despliegue y mantenimiento por host.
- **WIDS/WIPS:** vigila el entorno inalámbrico, por ejemplo AP no autorizados, ataques de desautenticación o configuraciones Wi-Fi inseguras.

### Métodos de detección

| Método | Ventaja | Limitación |
|---|---|---|
| Firmas | Preciso frente a amenazas conocidas; más fácil de explicar | Requiere actualización y puede no detectar amenazas nuevas o variantes |
| Anomalías / comportamiento | Puede alertar sobre actividad desconocida respecto a una línea base | Genera más falsos positivos si la base es pobre o el entorno cambia |
| Reglas / heurística | Detecta combinaciones de señales y políticas | Necesita afinado y revisión de cobertura |

Las alertas solo son útiles con reloj sincronizado, contexto de activos, retención de registros, responsables y un procedimiento de respuesta. Ajustar un IDS/IPS es un proceso continuo, no una configuración de una sola vez.

## 4. Appliances y puntos de control de red

### Balanceador de carga y ADC

Un **balanceador de carga** distribuye solicitudes entre varios servidores y realiza health checks. Mejora rendimiento y disponibilidad al retirar del servicio los nodos que no responden. Un **ADC** (Application Delivery Controller) puede añadir funciones de capa de aplicación, como terminación TLS, cache o reglas de entrega.

No elimina todos los puntos únicos de fallo: el propio balanceador, el DNS, la base de datos y las dependencias deben tener redundancia proporcional. Si termina TLS, protege claves privadas, usa cifrado moderno hacia los backends cuando corresponda y registra las decisiones de enrutamiento.

### Proxy

Un **proxy directo** intermedia solicitudes de clientes hacia Internet; puede autenticar usuarios, filtrar destinos, aplicar políticas y registrar navegación. Un **proxy inverso** recibe tráfico externo delante de servidores publicados; oculta los backends, permite terminación TLS, filtrado y distribución de carga.

El proxy reduce exposición directa, pero no convierte por sí solo un servicio en seguro. Debe endurecerse, actualizarse, tener reglas de origen correctas y no confiar en cabeceras que un cliente pueda falsificar.

### Sensores, TAP y SPAN

Los sensores proporcionan telemetría para rendimiento y seguridad. Un **TAP** copia tráfico de forma física/pasiva; un puerto **SPAN/mirror** configura un switch para replicar tráfico a un sensor. Ambos dan visibilidad sin poner el sensor en la ruta, pero pueden perder paquetes si el puerto de monitorización se satura y no permiten bloquear directamente.

### Jump server / bastion host

Un **jump server** o bastion host es un punto de administración reforzado desde el que se accede a sistemas de zonas protegidas. Reduce la exposición de SSH, RDP y consolas administrativas.

Debe ser un activo especialmente protegido: MFA, cuentas separadas de administración, privilegio mínimo, allowlisting, parcheado prioritario, registro de sesión, restricciones de origen/destino y sin navegación o correo de uso general. No es un servidor «intermedio cómodo»: es un objetivo de alto valor.

## 5. Control de acceso a la red: port security y 802.1X

### Port security basada en MAC

La seguridad de puerto en un switch limita qué direcciones MAC pueden utilizar un puerto. Puede restringir el número de MAC aprendidas, fijar una lista permitida y tomar acciones ante una violación. Ayuda a frenar conexiones casuales no autorizadas y algunos ataques de saturación de la tabla CAM.

No es una identidad fuerte: una MAC puede observarse y suplantarse. El aprendizaje «sticky MAC» simplifica operación, pero puede aprender el dispositivo equivocado si no se controla el momento de conexión. Deshabilita puertos físicos sin uso y combina este control con 802.1X, segmentación y seguridad física.

### 802.1X y EAP

**802.1X** es un estándar de control de acceso basado en puerto para redes cableadas e inalámbricas. Antes de conceder acceso normal, autentica al usuario o dispositivo. Intervienen tres roles:

| Rol | Función |
|---|---|
| **Supplicant** | Cliente que solicita acceso, como un portátil |
| **Authenticator** | Switch o punto de acceso que controla el puerto |
| **Servidor de autenticación** | Normalmente RADIUS; valida credenciales, certificados o políticas |

**EAP** es un marco de métodos de autenticación transportado por 802.1X, no un único método. EAP-TLS usa certificados en cliente y servidor y ofrece autenticación mutua robusta, a costa de requerir PKI y gestión de certificados. Métodos basados solo en contraseña o mecanismos antiguos como EAP-MD5 y LEAP no son una elección moderna adecuada para una red empresarial nueva.

RADIUS se usa de forma habitual para acceso de usuarios y dispositivos; TACACS+ se utiliza con frecuencia para administración de dispositivos de red y ofrece capacidades AAA detalladas. La decisión depende de la plataforma, la integración de identidad y el caso de uso, no solo del fabricante de los switches.

## 6. Comunicaciones seguras: VPN, TLS e IPsec

La protección de datos en tránsito busca confidencialidad, integridad, autenticación y, cuando aplica, protección frente a repetición. El cifrado no reemplaza la autorización: un usuario autenticado no debe recibir acceso a recursos que no necesita.

### VPN

Una VPN crea una conexión protegida sobre una red no confiable. Los dos patrones principales son:

| Tipo | Conecta | Caso común |
|---|---|---|
| **Site-to-site** | Dos redes o gateways | Sede y sucursal |
| **Remote access / client-to-site** | Un dispositivo de usuario y la red corporativa | Teletrabajo |

Una VPN de acceso remoto exige MFA, validación de postura del dispositivo cuando sea posible, permisos por aplicación o segmento, límites de sesión, logs y protección del endpoint. Evita dar acceso plano a toda la red interna por el mero hecho de que el usuario se conectó.

#### Full tunnel frente a split tunnel

- **Full tunnel:** todo el tráfico del cliente pasa por el punto de seguridad corporativo. Centraliza inspección y políticas, pero consume capacidad y puede añadir latencia.
- **Split tunnel:** solo el tráfico destinado a recursos corporativos usa la VPN; el resto sale directamente a Internet. Mejora rendimiento y reduce backhaul, pero requiere controles de endpoint, DNS, proxy/SASE y políticas muy claras para no crear una ruta de pivote hacia la red interna.

No existe una elección universal: se evalúan datos, riesgo, experiencia de usuario, seguridad del equipo, aplicaciones cloud y capacidad de inspección.

### TLS y VPN web

**TLS** protege conexiones de aplicación, por ejemplo HTTPS. Valida el certificado del servidor, usa versiones modernas y configura adecuadamente cifrados y renovación de certificados. Una VPN «sin cliente» o portal web puede usar TLS para proporcionar acceso limitado mediante navegador; HTTPS normal no equivale automáticamente a una VPN corporativa completa.

**DTLS** adapta protecciones similares a TLS al transporte UDP y puede resultar útil para tráfico sensible a latencia. La elección depende del protocolo y la aplicación, no de una promesa genérica de que UDP sea siempre más rápido o adecuado.

### IPsec

**IPsec** protege tráfico IP y es común en VPN site-to-site y algunas VPN de acceso remoto. IKE negocia asociaciones de seguridad y claves. IPsec puede aportar autenticación, integridad, cifrado y protección anti-replay, según los protocolos y algoritmos configurados.

| Modo | Qué protege | Uso típico |
|---|---|---|
| **Transporte** | Protege la carga IP; conserva el encabezado IP original | Comunicación host a host |
| **Túnel** | Encapsula el paquete IP original dentro de un nuevo paquete | VPN entre gateways o redes |

ESP es el mecanismo habitual para aportar confidencialidad además de integridad/autenticación. AH proporciona integridad y autenticación, pero no cifrado y suele presentar problemas con NAT; no es la opción típica de VPN moderna. Ajusta MTU/MSS si el encapsulado produce fragmentación, en lugar de asumir que los paquetes grandes funcionarán por todas las rutas de Internet.

## 7. SD-WAN y SASE

### SD-WAN

Una **SD-WAN** usa principios de red definida por software para controlar y optimizar conectividad WAN entre sedes, centros de datos, usuarios y aplicaciones cloud. Puede elegir dinámicamente entre enlaces como Internet, banda ancha, MPLS o red celular según políticas, calidad y criticidad de la aplicación.

Beneficios: visibilidad central, aprovisionamiento más ágil, uso de varios enlaces, priorización de tráfico y mejor experiencia para aplicaciones cloud.

Implicaciones: el controlador y la orquestación son activos críticos; protege sus APIs, identidades, certificados, cambios y disponibilidad. Cifra los overlays cuando corresponda y no asumas que seleccionar un enlace barato lo vuelve seguro sin controles adicionales.

### SASE

**SASE** (Secure Access Service Edge) es un enfoque cloud que combina capacidades WAN con servicios de seguridad entregados cerca del usuario o de la aplicación. Puede integrar, según la solución, SWG, CASB, firewall como servicio, ZTNA, inspección y políticas de identidad.

| SD-WAN | SASE |
|---|---|
| Se centra en conectividad y selección inteligente de caminos WAN | Integra conectividad con una plataforma de seguridad cloud y políticas de acceso |
| Puede ser parte de una solución SASE | Requiere definir identidad, postura, datos, proveedor y política, además de la conectividad |

SASE encaja especialmente en organizaciones con usuarios remotos, SaaS y múltiples ubicaciones. No es una garantía automática de zero trust: hay que verificar identidad, dispositivo, contexto, autorización por recurso, logs y obligaciones del proveedor.

## 8. Decisiones de infraestructura y ubicación

### Ubicación de dispositivos

La ubicación determina qué tráfico puede inspeccionar un control y qué sucede si falla. Sitúa el firewall en las fronteras de zona, el IPS donde deba bloquear, el sensor donde tenga visibilidad útil y los sistemas de gestión en una red administrativa separada.

Para Wi-Fi, diseña cobertura y capacidad sin irradiar señal innecesariamente fuera de las instalaciones. Separa SSID corporativo, invitados e IoT; aplica autenticación adecuada y evita que la red de invitados alcance recursos internos.

### Superficie de ataque

La superficie de ataque incluye interfaces, puertos, APIs, cuentas, dispositivos, servicios y relaciones de confianza que un atacante puede intentar usar. Crece con cada activo no gestionado, puerto expuesto, cuenta excesiva, servicio heredado o integración de terceros.

Reduce superficie retirando activos obsoletos, deshabilitando funciones y puertos no usados, endureciendo configuraciones, manteniendo inventario, segmentando, aplicando parches y revisando privilegios. «Ocultar» un servicio no es un control suficiente si sigue expuesto.

### Conectividad

| Medio | Ventaja | Riesgo o limitación |
|---|---|---|
| Cableado / fibra | Estabilidad, capacidad y menor exposición radioeléctrica | Requiere infraestructura física; también necesita control de puertos y acceso físico |
| Wi-Fi | Movilidad y despliegue flexible | Cobertura fuera del edificio, interferencias, AP no autorizados y configuración deficiente |
| Celular / satélite / radio | Alternativa o respaldo en ubicaciones remotas | Coste, latencia, cobertura y dependencia de proveedor |
| Enlaces diversos | Resiliencia ante caída de un medio | Exigen pruebas de failover y políticas coherentes |

### Controles activos, pasivos, inline y out-of-band

| Característica | Efecto | Ejemplo |
|---|---|---|
| Activo | Puede modificar, bloquear o redirigir tráfico | Firewall, IPS, proxy inline |
| Pasivo | Observa o copia tráfico sin intervenir | IDS mediante TAP o SPAN |
| Inline | Está en la ruta; puede detener tráfico | IPS/WAF en modo de bloqueo |
| Out-of-band | Recibe copia; no bloquea directamente | Sensor NIDS o WAF de monitorización |

Un control inline ofrece prevención inmediata, pero añade latencia y riesgo de corte por fallo o falso positivo. Un control pasivo da visibilidad segura para el tráfico, pero necesita un proceso posterior de respuesta.

### Fail-open y fail-closed

| Modo ante fallo | Prioriza | Consecuencia |
|---|---|---|
| **Fail-open** | Disponibilidad | Deja pasar tráfico o permite una función sin inspección; aumenta exposición |
| **Fail-closed** | Confidencialidad e integridad | Bloquea tráfico o acceso; puede interrumpir el servicio legítimo |

La elección depende del proceso protegido. En un segmento con datos altamente sensibles suele preferirse fail-closed; en otro servicio puede ser más importante continuidad. En sistemas críticos o de seguridad física pueden requerirse diseños redundantes, bypass controlado y procedimientos de emergencia en vez de elegir sin más entre seguridad y disponibilidad. Documenta, prueba y supervisa el comportamiento real de cada dispositivo.

## 9. Selección de controles por escenario

| Necesidad del escenario | Controles iniciales apropiados |
|---|---|
| Publicar una aplicación web | DMZ/screened subnet, firewall restrictivo, WAF, hardening, TLS, logs y separación de base de datos |
| Detectar sin interrumpir tráfico crítico | NIDS pasivo con TAP/SPAN, logs centralizados y procedimiento de respuesta |
| Bloquear explotación conocida en el perímetro | IPS inline ajustado, firewall/NGFW y plan para falsos positivos |
| Impedir que un equipo no autorizado use una toma de red | Puertos no usados deshabilitados, 802.1X/EAP, VLAN de cuarentena y seguridad física |
| Administrar servidores críticos | Jump server endurecido, MFA, cuentas separadas, segmentación y grabación/log de sesiones |
| Conectar una sucursal | VPN site-to-site/IPsec o SD-WAN, segmentación y redundancia de enlaces según criticidad |
| Proteger teletrabajo | VPN o ZTNA, MFA, postura/gestión de endpoint, privilegio mínimo y registros |
| Usuarios y SaaS distribuidos globalmente | SASE con identidad, políticas por recurso, protección de datos y revisión del proveedor |
| Evitar caída de una aplicación muy utilizada | Balanceador redundante, health checks, varios backends y pruebas de recuperación |

## Errores frecuentes

- Confundir IDS con IPS: el IDS alerta; el IPS puede bloquear porque está en línea.
- Tratar las direcciones MAC como una autenticación fuerte: pueden suplantarse.
- Exponer RDP, SSH, SMB o consolas directamente a Internet por comodidad.
- Considerar que una DMZ permite tráfico libre hacia la red interna.
- Usar una UTM sin alta disponibilidad ni dimensionamiento y convertirla en un punto único de fallo.
- Asumir que HTTPS o una VPN autorizan todo el acceso; aún se necesita autorización granular.
- Configurar split tunnel sin controles de endpoint, DNS y política de salida.
- Instalar un IPS/WAF inline sin modo de prueba, capacidad suficiente ni plan de reversión.
- Elegir fail-open solo para evitar cortes sin aceptar el riesgo de quedar sin inspección.

## Resumen

- Protege la infraestructura mediante defensa en profundidad: segmentación, reglas mínimas, identidad fuerte, cifrado, monitorización y recuperación.
- Firewalls y ACL controlan flujos; WAF protege aplicaciones web; IDS detecta e IPS detecta y bloquea.
- Port security es un apoyo, mientras que 802.1X/EAP aporta control de acceso más sólido.
- VPN, TLS e IPsec protegen comunicaciones, pero requieren MFA, autorización, configuración y gestión de claves correctas.
- SD-WAN mejora conectividad WAN; SASE integra conectividad y seguridad cloud para entornos distribuidos.
- La ubicación, modo inline/pasivo y elección fail-open/fail-closed cambian tanto el nivel de seguridad como la disponibilidad.
